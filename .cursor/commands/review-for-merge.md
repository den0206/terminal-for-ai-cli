# マージ前レビュー（取り込み可否の判定）

現在の未コミット変更（またはブランチの差分）を**厳密にレビュー**し、マージの安全性とコード品質を担保する。

## 手順

### 1. 変更の把握

- `git status -s` と `git diff`（未追跡は該当ファイルを読む）で**変更内容をすべて把握**する。
- ブランチの差分を見る場合は `git log --oneline <base>..HEAD` と `git diff <base>...HEAD` を使う。
- 変更ファイル一覧と差分の概要を簡潔にまとめる。

### 2. 品質チェックの実行

以下を**必ず**実行する。

| チェック | コマンド | 合格基準 |
|----------|---------|----------|
| TypeScript 型チェック | `npx tsc --noEmit` | エラー 0 |
| ESLint | `npm run lint` | エラー 0（警告は許容） |
| テスト | `npm run test` | 全テスト合格 |

3 つとも独立して実行できるため、**並列に実行**してよい。

### 3. 厳密レビュー観点

以下を**必須**で確認する。

| 観点 | 確認内容 |
|------|----------|
| **セキュリティ** | シェルパスのエスケープが `escapeShellPath` 経由か。ユーザー入力（ファイル名・パスなど）がサニタイズされているか。`node-pty` の spawn に外部入力が直接渡されていないか。 |
| **リソース管理** | `Disposable` が適切に実装・登録されているか。イベントリスナーのクリーンアップ漏れがないか。PTY プロセスの終了処理（SIGTERM → SIGKILL）が正しいか。 |
| **型安全性** | `as unknown as` などの危険なキャストに正当な理由があるか。`any` が不必要に使われていないか。shared types との整合性が取れているか。 |
| **Webview / Extension 間通信** | `InboundMessage` / `OutboundMessage` の型定義と実際の `postMessage` が一致しているか。メッセージハンドラの `switch` で exhaustive check が漏れていないか。 |
| **パフォーマンス** | throttle / debounce が適切に使われているか。バッファサイズの制限（`MAX_BUFFER_SIZE`）が守られているか。不要な `fitVisibleTerminals()` の連続呼び出しがないか。 |
| **整合性** | 新規コードが既存のパターン（コントローラ抽出パターン、コールバック注入など）に従っているか。未使用の import が残っていないか。 |
| **保守性** | マジックナンバーが `Constants` / `SHARED_CONSTANTS` に定義されているか。不必要なコメントがないか。 |

### 4. レビュー結果の出力形式

以下の形式で**必ず**出力する。

```
## 変更概要
- （変更ファイルと役割の一行サマリ）

## 品質チェック
- TypeScript: （結果）
- ESLint: （結果）
- テスト: （結果 — N ファイル M テスト合格）

## マージ安全性
- **ブロッカー（必須で直す）**: （あれば箇所と理由、なければ「なし」）
- **強く推奨（直すべき）**: （あれば箇所と理由、なければ「なし」）
- **任意の改善**: （あれば簡潔に、なければ「なし」）

## 判定
- **取り込み可** / **要修正のため取り込み不可**
```

### 5. 判定基準

- **ブロッカーが 1 つでもある**、または **品質チェック（tsc / lint / test）がエラー** → **取り込み不可**。
- ブロッカーがなく、強く推奨のみ → **取り込み可**（修正を推奨するがマージは許可）。
- ブロッカーも強く推奨もない → **取り込み可**。

### 6. 次のアクション選択

レビュー結果の出力後、**判定に応じた選択肢**を `AskQuestion` ツールで提示する。

#### 「取り込み可」の場合

| 選択肢 | 説明 |
|--------|------|
| **機能別にコミットを作成** | `/commit-by-feature` を実行して機能ごとにコミットする |
| **全変更を一括コミット** | すべての変更を 1 つのコミットにまとめる |
| **強く推奨の項目を先に修正** | 強く推奨がある場合のみ表示。指摘を修正してから再レビューする |
| **何もしない** | レビュー結果の確認のみで終了する |

#### 「取り込み不可」の場合

| 選択肢 | 説明 |
|--------|------|
| **ブロッカーを自動修正** | 指摘されたブロッカー（と強く推奨）を修正し、再度レビューを実行する |
| **何もしない（手動で直す）** | レビュー結果を参考に手動で修正する |

## 注意

- レビューは**コードの内容に基づいて**行う。推測で「多分大丈夫」にしない。
- セキュリティ（シェルインジェクション防止）とリソースリーク防止を最優先する。
- `AskQuestion` の選択肢は判定結果に応じて動的に変える。
